# Contributing to Xun Development

Start with the shared [local manifest](https://github.com/Xun-Development/local_manifests/tree/lineage-24.0)
and select the repository that owns the component you are changing.

Use that repository's default branch as the pull-request base. Keep each change focused,
preserve upstream authorship and license headers, and explain which device or shared
component is affected. For shared platform changes, identify whether xun, fog or both
were checked.

Include the commands you ran and their results. Distinguish compilation, static checks
and device runtime testing; state explicitly when a check was not performed.

For build or runtime reports, use the [issue form](https://github.com/Xun-Development/local_manifests/issues/new/choose)
and include the build revision, reproduction steps and relevant diagnostic output when available.
